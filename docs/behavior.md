# Transfer details

See the [README](../README.md) for installation and usage.

## What transfers

| Content              | Behavior                                                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Git history          | Local branches, tags, and the selected HEAD, including unpushed commits.                                         |
| Working tree         | Tracked files, staged and unstaged changes, non-ignored untracked files, executable bits, and internal symlinks. |
| Claude conversations | Native transcripts and saved subagent transcripts; the destination imports them through Paseo.                   |
| Codex conversations  | Native rollout files; the destination imports them through Paseo.                                                |
| Names and labels     | Workspace name and agent titles, labels, and archived state.                                                     |
| Directory workspaces | Plain files; `.git`, `node_modules`, `.venv`, and `__pycache__` directories are excluded.                        |

Git-ignored files such as `.env`, dependencies, provider credentials, daemon credentials, repository config/hooks, terminals, schedules, workspace pins, and provider-specific launch settings stay on the source. Imported agents use the target host's provider configuration. Conversation text stays intact; only structural `cwd` fields are translated.

Unsupported providers or missing saved conversations block the transfer rather than silently dropping history. Submodules, repositories without a commit, Git subdirectory workspaces, unmerged Git indexes, and escaping symlinks are not supported.

## Large transfers in the Impower fork

Connected transfers use protocol 2: a private disk-spooled archive with length-delimited binary blobs, per-blob SHA-256 digests, a bounded metadata manifest, and a full wire checksum. Files, Git bundles, index patches and native transcripts never become one large JSON/base64 string. The existing ordered 192 KiB RPC chunks relay the archive; receiver extraction reads at most 256 KiB of file data at a time. Both hosts must run the same protocol; upstream protocol 1 is refused.

The host-scoped `limits` settings are registered through Paseo's settings API. Defaults are `maxFiles: 100000`, `maxBytes: 17179869184` (16 GiB including archive framing), `maxFileBytes: 4294967296` (4 GiB), `commandTimeoutSeconds: 900`, and `taskTimeoutSeconds: 3600`. Zero removes a file/byte policy limit. Integer validation, bounded framing, path checks, destination ownership and digest verification remain mandatory. The receiver applies its own limits and requires temporary free space for the upload, extracted verification data and destination. Source and destination settings can differ; a stricter destination refuses the upload or extraction.

`transfer.identity` advertises `protocol: 2` and the host's task timeout. Connected task polling uses that advertised bound. Large Git bundle creation, fetch, checkout and binary-index operations use the configured command bound. The transfer's chunk-relay loop is not constrained by the former fifteen-minute task constant. The compact manifest is bounded to 64 MiB and each native transcript JSONL row to 16 MiB; malformed or oversized metadata is refused without source archival.

The **Use SSH** Preview/Start route uses the same raw archive for local-to-SSH, SSH-to-local and SSH-to-SSH transfers. Worker code and small control messages travel separately from the binary payload. An authenticated source SSH process feeds a bounded binary pipeline into an authenticated destination SSH process; SSH-to-SSH traffic is relayed by the controlling host, with no reverse access required. Normal SSH aliases, agent/key selection and host-key verification remain in force. The controller never holds the complete archive in memory. Stream endpoints use private 0700 temporary directories and exclusive 0600 files, reject symlink/non-regular archive handles, enforce the declared wire size and configured byte cap, and confirm SHA-256 before receive. Stream buffers are 256 KiB; control responses are bounded to 16 MiB and the bootstrap to 4 MiB.

The initiating plugin's host-scoped limits are passed explicitly to both standalone SSH workers, including the configured command timeout for large Git operations and task timeout for each worker/stream operation. A preview exports and checks metadata, releases its spool, and keeps only a fingerprint. Start exports again, compares that fingerprint, streams to a separately allocated destination spool, verifies/imports natively, and only then runs the separate fresh guarded archive operation for Move. Temporary source/upload spools are released on completion and failure; unavailable cleanup reports the exact private handle for recovery. A hard process kill can leave a private temporary directory. The internal version-1 snapshot API remains for compatibility, but the supported SSH UI no longer calls it or inherits its 128 MiB JSON payload limit.

For a source that cannot load the 0.14 plugin, the generated standalone worker also exposes `archive-export`, `archive-receive`, `archive-source`, and `archive-release` through `dispatch` and the existing `server/transport.ts` SSH runner. These use the selected host's supported local CLI (minimum 0.11), without plugin hooks or daemon restart. `archive-export` takes `workspaceId` and optional `limits` and returns a private archive file handle, source server/workspace/session metadata, fingerprint, byte count and checksum. Copy that binary file through an authenticated file transport rather than embedding it in a command/RPC envelope. `archive-receive` takes the uploaded `file`, its required `checksum`, a new `destination`, and optional `limits`; it checks the complete wire checksum before extracting and returns the new native IDs. `archive-source` is a separate explicit operation taking the original workspace ID and fingerprint, with fresh running-writer, ignored-file and source checks before native archive. `archive-upload` takes `wireBytes` and optional `limits`, checks temporary free space and allocates a private upload handle. `server/transport.ts` exports `copyArchive(sourceEndpoint, targetEndpoint, exportedMetadata, uploadFile, limits)` to stream that handle through the same authenticated SSH route. `archive-release` removes only a private export/upload spool whose exact archive handle the worker returned. Both source and destination must still be qualified against their actual CLI/runtime and external ownership holds before real work moves. CLI calls honor an explicit `PASEO_SYNC_CLI` unchanged, then prefer an executable `paseo` on PATH. If a macOS GUI daemon has no CLI on PATH, the worker checks only the current process's app resources/enclosing app and `/Applications/Paseo.app` or `~/Applications/Paseo.app` for the existing executable `Contents/Resources/bin/paseo`. It does not alter PATH or install a CLI. A selected CLI's execution or compatibility failure is reported without switching to another installation. Linux/WSL keep POSIX PATH lookup and do not search macOS bundles.

Automation can use `client/connected-transfer.ts`'s exported `createTransferClient(getRpc)` with an authenticated per-server RPC function. `preview({sourceId,targetId,workspaceId,destination,mode})` returns a fingerprint-bound plan; `start(plan)` returns a run ID; `status(runId)` reports completion and the exact new workspace/agent IDs. The injected RPC calls `DaemonClient.invokePluginRpc("transfer", contract.name, input)` and validates `contract.output`. This is the same preview/re-export/ordered upload/receive/final source-check flow used by the UI, not a bypass. Native agent tools remain read-only discovery/status tools.

Copied provider session IDs stay the same, while Paseo workspace and agent IDs are new. Pins, hierarchy, workspace Info fields, remote Git configuration and owner-tracker relations require separate verified reconciliation. No provider turn is started by an archive transfer. The fork checks all running agents' real checkout paths, including distinct workspace IDs sharing one directory; external ownership and do-not-archive holds still belong to the operator's preflight.

Source checkout handoff stays exclusive until native archive completes; sibling worktrees in the same Git repository may continue working. Export retains before-read file/link tokens and a change journal, then checks the complete file inventory, this checkout's Git HEAD/logical branch value/index/ignored paths, selected workspace and conversation inventory after the long scan. A move retains that fence through a final idle probe and source check. Observed changes or unavailable monitoring retain the source. These checks do not replace the existing owner handoff with an atomic filesystem transaction.

The handoff fingerprint binds this source checkout's HEAD, branch, index, working files and sessions, independently of other common-repository refs. Shared ref packing may move an unchanged branch between loose and packed storage; logical-value checks allow that maintenance while source branch changes and its reflog activity still hold the transfer. Additional branches/tags are captured as fixed ref hashes in a private bare snapshot borrowing the source's immutable object database, with hooks disabled and no source ref/config writes; its bundle is verified. Each export can include a newer consistent snapshot of those additional refs while the source checkout stays unchanged. The full archive manifest digest and wire/blob checksums still bind the exact transferred bundle. Native managed-worktree archive removes the selected checkout while preserving the common repository and sibling branches/worktrees; the fork verifies that behavior in isolated native fixtures.

The receiver bounds blob count before extraction (the configured counted-file allowance plus two Git blobs), and framing/manifest metadata remains bounded even when file/byte policy limits are zero. An ambiguous native-create response preserves destination files and transcripts, reconciles native inventory for evidence, and requires reconciliation before a retry; an immediate absent result does not prove a delayed create cannot settle.

## Verification and recovery

Transfer refuses an occupied destination or an existing native session ID. It verifies file bytes, modes, symlinks, Git HEAD, staged changes, transcript bytes, agent imports, and workspace registration. It never overwrites an existing checkout or edits Paseo's workspace/agent registry files.

A failure before any workspace registration attempt removes the new destination. A failure after registration, or with an uncertain native-create acknowledgement, preserves the partial destination for recovery and reports its path. The source stays open. If archiving fails or the source changes during a move, the verified destination remains available and the source stays open. Plugin reloads clear preview/status state; check both hosts before retrying a transfer interrupted by reload.

Connected transfers reuse Paseo's configured hosts and authenticated plugin RPCs, following Transcript Search's host federation. Each host operates on its own filesystem; the client relays bounded chunks with an end-to-end checksum. Hosts are matched by server ID, never by label or address, and a disconnected or missing installation never falls back to another host. Both hosts need the same protocol-2 fork commit. Keep the app open and both hosts connected; closing only the popup is safe. Once the destination starts receiving, it finishes on that host even if the app disconnects. A lost connection before confirmation leaves the source open; check the target before retrying.

Connected previews hold a snapshot in a private temporary directory on the source. Starting rechecks the source checksum before uploading a fresh snapshot. Temporary data is released after use, when a preview is dismissed, on plugin cleanup, or lazily after 30 minutes of inactivity when another request arrives. A killed process can leave temporary files in the operating system's temporary directory. No credentials or new connection tokens are sent to the client.

**Use SSH** retains the single-plugin workflow with normal host-key verification. Git bundles travel over that connection, so the receiving host does not need reverse SSH access. SSH previews retain only metadata and a checksum. SSH automation starts `transfer.preview.start` with explicit `source` and `target` endpoints, then polls `transfer.preview.status` by `previewId` for the plan before calling `transfer.run` and `transfer.status`. An empty endpoint `target` string denotes the controlling host. `client/ssh-preview.ts` exports `waitForSshPreview(input, startRpc, statusRpc)` for that same flow. Preview start returns immediately with its configured timeout budget: long exports run behind short status calls, so the daemon client's sixty-second per-request deadline does not constrain payload size. The original synchronous `transfer.preview` contract remains for compatibility; use the polled contract for large exports. The returned run includes new native workspace and agent IDs, while provider session IDs remain unchanged.

Home directories, filesystem roots and ancestors of the home directory are refused before scanning. This avoids walking protected folders such as macOS Trash. Permission failures in project directories are reported with the failing path and recovery guidance; unreadable files are never silently skipped.
